# Mule Create

Die Oberfläche gibt es auf Deutsch und Englisch: **Ansicht → Sprache / Language** (gilt nach dem Neustart, auch fürs Handbuch). Diese Datei ist die ausführliche deutsche Funktionsliste; Überblick auf Englisch: `README.md`, vollständige Dokumentation für KI-Assistenten: `AI_HANDBOOK.md`. Offizieller Name: **Mule Create** (kurz Mule); das Programm hieß früher Sketch Machine; Paketname, Einstellungen, Szenenformat und MCP-Server heißen intern weiter so.

Standalone-Tool zum technischen Skizzieren im 3D-Raum – mit Linien. Ebenen und Zeichenflächen sind nur Hilfsmittel, auf denen man zeichnet. Man zeichnet auf Ebenen, die im Raum aufgespannt werden; die Ausgabe ist eine strukturierte Datei, die eine KI in ein prozedurales Houdini-Setup übersetzen kann.

Kurzanleitung für Tester (Installation, wichtigste Abläufe, KI-Anbindung, Probleme melden): `ANLEITUNG.md`, Änderungen: `CHANGELOG.md`.

Braucht OpenGL 3.3. Importierte Geometrie wird in der Szene als relativer Pfad gespeichert;
USD ohne eingetragene `metersPerUnit` gilt als Meter, Z-up-Dateien werden auf Y-up gedreht.

## Start (Windows)

```
py -3.14 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m sketch_machine
```

oder Doppelklick auf `start.bat` (richtet beim ersten Start `.venv` selbst ein und installiert fehlende Pakete nach). Von Hand nach einem Update mit neuen Paketen einmal
`.venv\Scripts\pip install -r requirements.txt` ausführen.

## Start (Linux)

```
./start.sh
```

Die App bringt ihr eigenes Python mit (wie Houdini oder Blender). Beim ersten Start legt `start.sh` mit
[uv](https://docs.astral.sh/uv/) ein eigenständiges **Python 3.14 im Projektordner** an (`runtime/python`) und
daraus `.venv` mit genau den Versionen aus `requirements.txt`. Das System-Python (z. B. 3.9 im Studio) wird weder
benutzt noch verändert, Admin-Rechte sind nicht nötig. Danach startet die App ohne uv und ohne Internet – auch
für andere Nutzer, die den Projektordner lesen können. Eine ältere `.venv` wird beim Einrichten nach
`.venv.alt-<Datum>` verschoben (kann gelöscht werden). Kommen neue Pakete dazu (scipy ist Pflicht – Flächen brauchen es, einen
Ersatzweg ohne gibt es nicht mehr), installiert `start.sh` sie beim nächsten Start in die bestehende `.venv` nach (einmal Internet nötig).

Voraussetzungen nur fürs erste Einrichten: uv (ohne Admin-Rechte: `curl -LsSf https://astral.sh/uv/install.sh | sh`)
und Internet. Zum Laufen: OpenGL 3.3 (Grafiktreiber des Rechners, NVIDIA oder Mesa). Meldet Qt „Could not load the
Qt platform plugin xcb“, fehlt eine Systembibliothek (`libxcb-cursor0`). Unter Wayland notfalls mit
`QT_QPA_PLATFORM=xcb ./start.sh` starten. Stürzt die App ab, steht die genaue Stelle im Terminal
(`PYTHONFAULTHANDLER` ist gesetzt).

Versionen: alle Pakete sind in `requirements.txt` fest auf den getesteten Stand gepinnt (gleich auf Windows und
Linux). PySide6 6.12.0 stürzte unter Linux mit Python 3.10 im Viewport ab („deallocating None“) – ab Python 3.12 ist
dieser Fehler harmlos; nicht ohne Test aktualisieren, Ausweichversion wäre 6.10.

Grafiktablett (Wacom): der Stift wirkt wie die Maus (Spitze = linke Taste, Seitentasten nach Treiber-Belegung,
z. B. mittlere/rechte Taste). Druck steuert je nach Regler Strichbreite und Radiergröße (mit der
Maus spielt der Druck keine Rolle). Bei mehreren Monitoren den Tablettbereich im Treiber auf einen Monitor legen.

## Tests

`.venv\Scripts\python.exe tests\run.py` startet alle Tests (`tests/test_*.py`, jede Datei in einem eigenen
App-Fenster außerhalb des Bildschirms, mit echten Maus- und Tastenereignissen; die echten Einstellungen bleiben
unberührt). Namen als Filter: `tests\run.py topology scenes`. Ergebnis je Test: OK, FEHLER, ERWARTET (bekanntes
Problem, das ein späterer Schritt lösen soll) oder BEHOBEN (bekanntes Problem gelöst – Markierung entfernen).
Testszenen Gießkanne, Teetasse, Pferdekopf liegen in `tests/scenes/` (in der App öffnen), Bilder der Läufe in
`tests/_out/`. Der Pixelvergleich legt beim ersten Lauf Referenzbilder in `tests/_baseline/` an (pro Rechner);
nach gewollten Änderungen der Darstellung `tests\run.py render --update-baseline`.

| Punkte: Linienenden und Ecken (Knick ab 30°, beim ersten Gebrauch erkannt und an der Linie gemerkt); alle Punkte werden als kleine Kreise gezeigt. Verschieben ist weich: die Linie läuft bis zu den Nachbarpunkten aus (gerade Stücke bleiben gerade), verbundene Linienenden an derselben Stelle wandern mit (Alt: nur das Gewählte). Strg + Klick auf eine Linie fügt einen Punkt ein. Entf löst gewählte Punkte auf: die Linien behalten exakt ihre Form; Ecken und eingefügte Punkte verlieren nur ihren Griff, an einem Stoß zweier Linienenden werden die beiden Linien eine durchgehende Linie (auch auf dem Rand einer Kurvenfläche – die Fläche bleibt, wie sie ist). B. eine Verbesserung an einer Notiz, die Claude geschrieben hat: ersetzt ein eindeutiges Textstück auf dem Brett, auf Wunsch auch die Überschrift; ein Undo-Schritt, Strg+Z nimmt es zurück). Von sich aus ändert Claude keine Notiz – außer den eigenen Review-Entwürfen. **review_read**, **review_moment**, **review_note**: Review-Aufnahmen lesen, ihre Momente ansehen und Entwurfs-Notizen anlegen (siehe Review). **insert_images**: Bilddateien aus Ordnern aufs Brett legen wie beim Hineinziehen (Referenzordner, „Hier!“-Bilder eines Reviews, Renders) – nur Bilder, die Claude angesehen hat und die klar dazugehören, sonst fragt es; auf Wunsch mit Bildunterschrift und Pfeil vom Text; dieselbe Datei nicht doppelt, Strg+Z nimmt es zurück | Claude-Chat |
| **Szene als USD exportieren** (Menü Datei → Exportieren): die Szene kompakt für Houdini, Blender, Maya – Hierarchie wie im Outliner (Nulls als Xform, Objekte darunter, alles in Weltkoordinaten; Ursprung/Achsen der Nulls als sketch:origin/axes), Flächen als Polymeshes (Lofts, Kurvenflächen, Extrusionen als Quads aus ihrem Raster, Füllflächen als Dreiecke; Normalen je Ecke wie im Viewport – harte Kanten bleiben hart –, UV in Metern, displayColor, Material als Primvar; Hilfsflächen als guide), Linien als BasisCurves (Breite, Farbe, orient/pscale, Härte), importierte USD-Meshes **referenziert** (relativer Pfad, nichts kopiert; Lage als Matrix, die Lage in der Quelldatei eingerechnet), OBJ eingebettet, Symmetrie und Array **herausgerechnet** (jede Kopie ein eigener Prim „…__copyN“, an der Spiegelebene geschnitten; Einstellungen stehen am Generator-Xform), Notizen als Punkte. Nur Sichtbares, Kennungen wie im Sketch Brief. Auflösung der Raster-Flächen als Vielfaches der im Viewport (0,25–4, Standard 0,25 – der Viewport ist zum glatten Anzeigen sehr dicht). .usd/.usdc binär, .usda als Text | Strg + Shift + E |
| **Kurven exportieren** (Menü Datei → Exportieren → Kurven): nur Linien und Malerei mit Dicke je Punkt, ohne Flächen, Meshes und Notizen. Format wählbar: USD für Houdini, Blender, Maya oder JSON (`name.curves.json`, lesbarer Text) für Skripte und KI-Chats. Hero-Kameras kommen mit, Ausgeblendetes auf Wunsch, exakt doppelte Striche fallen weg, Röhren (USD) auch um Malerei. | Menü |
| **Review** (Menü Ansicht → Review bzw. Knopf „Review“): durch die Szene gehen und Feedback einsprechen wie in einer Review-Session – Mule nimmt die Stimme übers Mikrofon auf (Standard des Systems, anderes im Untermenü „Mikrofon“) und schreibt mit, wo die Kamera war, worauf der Cursor zeigte (wenn er kurz ruht), was gewählt und welches Brett offen war; **Werkzeug „Markieren“** (Knopf neben „Review“, beim Start an): gestrichelter Ring am Cursor, magenta wenn etwas getroffen würde, die Statusleiste nennt das Teil; **Klick** setzt die Marke – Bild, Kamera und was genau dort liegt; der Klick geht nicht ans Werkzeug, mit Alt oder Leertaste navigiert man wie immer, **Strg+Z** nimmt die letzte Marke zurück, Knopf aus = normal weiterarbeiten (die Aufnahme läuft weiter). Ein Klick auf ein Bild im offenen Brett ist eine **Brett-Marke** (Bild und Stelle darin): Claude legt dieses Bild mit Pfeil in die Notiz zum Teil, es bleibt auch auf seinem Brett. Gesetzte Marken stehen als magenta Stecknadeln mit Nummer im Viewport, bis das Review endet (grauer Ring mit „?“, wenn nichts getroffen wurde). Pfeile und Anker der Entwürfe sitzen nur dort, wo wirklich gezeigt wurde: Marke bis 4 s daneben, sonst ein gesprochenes „hier/dort/here/there“ bei stillem Cursor und stiller Kamera (Wortzeiten von Whisper), sonst ein kurz ruhender Cursor – sonst kein Pfeil statt eines geratenen. Notizen so wenig wie möglich, so viele wie nötig: eine je Bauteil oder Bereich, mit Stichpunkt-Gruppen und einem Bild je Stelle. Kein Video: Mule rendert jeden Moment danach neu. Nach dem Ende transkribiert faster-whisper lokal im Hintergrund (Grafikkarte, sonst Prozessor). **Einrichten:** beim ersten Review fragt Mule nach (Einrichten / Später / Nicht mehr fragen), sonst Review-Menü → „Transkription einrichten …“ – braucht einmalig ein Python 3.10–3.13 von python.org (Haken „Add python.exe to PATH“); Mule legt `%APPDATA%/Mule/whisper_venv` an, installiert faster-whisper (bei NVIDIA mit CUDA-Bibliotheken) und lädt das Modell, zusammen etwa 2–4 GB. Für Fortgeschrittene geht auch ein eigenes Python mit faster-whisper: Einstellung whisper_python, Umgebung SM_WHISPER_PYTHON oder ~/mcp/whisper_venv. Ordner je Review unter `%APPDATA%/Mule/Reviews/` (ton.wav, protokoll.jsonl, marke_N.jpg, transkript.json). Danach im Claude-Chat: „Mach aus dem letzten Review Notizen“ – Claude liest Transkript und Zeigespur (MCP review_read), schaut sich die Stellen an (review_moment) und legt je Feedback-Punkt einen **Entwurf** an (review_note): Stichpunkte wie beim Diktieren, mit dem Bild abgeglichen, Notiz an dem Teil unter dem Cursor (Krake für mitgemeinte Teile), Bild aus deiner damaligen Kamera mit Pfeil auf die gezeigte Stelle. Entwürfe haben gestrichelte Klammern; im Brett steht dein Originalsatz, **▶ Anhören** spielt die Stelle, **✓ Übernehmen** macht eine normale Notiz. Der Brief nennt nicht übernommene Entwürfe als offenen Punkt. **Review absenden** (Knopf neben „Review“): beendet die Aufnahme, transkribiert, sichert die Szene in `review_backups/` neben der Szenendatei (je Szene die neuesten 20, Einstellungen → Review) und legt einen Satz in die Zwischenablage – im Claude-Chat „Review ist da“ schreiben bzw. einfügen. Der Knopf zeigt „Transkribiere …“, „Bereit – sag Claude Bescheid“ und, sobald Claude das Review liest, „Claude arbeitet …“ (dreht sich); die Entwürfe erscheinen **auf einmal live in der offenen Szene** (review_notes, ein Strg+Z), nichts wird automatisch gespeichert – du speicherst, wenn du sie durchgesehen hast. Mule startet Claude nicht selbst (ein Chat lässt sich von außen nicht anstoßen); jede MCP-fähige KI (z. B. Codex/GPT) kann dieselben Werkzeuge nutzen. Im Notizmodus steht das Menü „Review“ neben Shots; während der Aufnahme bleibt es in jedem Modus sichtbar (rot, mit Laufzeit), und Mule schreibt mit, was du selbst änderst (Notizen, Bilder, Linien) – Claude baut darauf auf | Werkzeug Markieren · Strg+Z |
| **Aufnahme** (Menü Ansicht → Aufnahme): schreibt jede Eingabe mit Zeitstempel in `protokoll.jsonl` (Tasten, Klicks mit Position, Menü-/Leisten-Aktionen, Moduswechsel), dazu die Rechendauer je Eingabe und Hänger ab 150 ms (ab 1 s mit kleinem Fensterbild). Ordner je Aufnahme unter `%APPDATA%/Mule/Aufnahmen/`. Text in Eingabefeldern wird nicht mitgeschrieben | Menü |
